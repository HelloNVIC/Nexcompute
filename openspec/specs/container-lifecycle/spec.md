## Requirements
### Requirement: 容器创建表单

用户 SHALL 通过表单创建容器。表单字段包含：选择镜像（仅限管理端已配置的镜像，下拉选择，不支持自由文本）、选择存储池（当前机器上用户拥有的或被共享授权的项目池，下拉展示各池状态）、资源限制（CPU、内存、SHM 为硬限制，GPU 显存为软限制）、声明容器内端口（SSH 22 + 自定义应用端口，所选镜像的应用端口自动预填，用户可增删）、设置容器 SSH 密码（必填）。资源限制字段 SHALL 默认填入当前用户可使用的最大值（取用户/课题组资源配额，无则取目标物理机总容量）并显示数值范围 [最小值, 最大值]。管理端根据表单生成 Docker 运行命令（MUST 包含 `--gpus all`、资源限制、端口映射），通过 WebSocket 下发给受控端执行。

#### Scenario: 学生创建容器
- **WHEN** 学生在分配到的物理实例上填写容器创建表单（含 SSH 密码）并提交
- **THEN** 管理端校验该学生有权使用该物理实例与所选存储池
- **AND** 管理端生成 Docker 运行命令（含 `--gpus all`、资源限制与端口映射）下发受控端
- **AND** 受控端调用 Docker API 创建并启动容器
- **AND** 容器启动后受控端注入 SSH 密码并回传端口映射结果
- **AND** 管理端向用户返回连接信息

#### Scenario: 资源限制默认值与范围
- **WHEN** 用户打开容器创建表单的资源限制字段
- **THEN** CPU/内存/GPU显存/SHM 默认填入当前用户可使用的最大值（用户/课题组配额，无则目标机总容量）
- **AND** 字段显示数值范围 [最小值, 最大值]
- **AND** 提交时后端校验限制不超过配额

#### Scenario: 镜像仅可选已配置镜像
- **WHEN** 用户在容器创建表单选择镜像
- **THEN** 下拉仅展示管理端已配置的镜像（自有/共享/公共库）
- **AND** 不允许自由文本输入镜像

#### Scenario: 容器内端口自动预填
- **WHEN** 用户选择某镜像
- **THEN** 该镜像的应用端口自动填入"容器内端口"
- **AND** 用户可增删端口，SSH 22 始终包含

#### Scenario: 无权使用该物理实例
- **WHEN** 用户尝试在未分配给自己的物理实例上创建容器
- **THEN** 系统拒绝并提示无权限
### Requirement: 端口自动分配

系统 SHALL 在容器创建时自动在目标物理机上分配宿主端口，映射到用户声明的容器内端口，防止单机端口冲突。端口分配表由管理端维护。

#### Scenario: 自动分配宿主端口
- **WHEN** 用户声明容器内端口（如 SSH 22、Jupyter 8888）
- **THEN** 管理端在该物理机上分配空闲宿主端口
- **AND** 生成的 Docker 命令包含 `-p 宿主端口:容器端口` 映射
- **AND** 端口分配记录存入管理端

#### Scenario: 端口冲突避免
- **WHEN** 物理机上某宿主端口已被占用
- **THEN** 系统自动选择下一个空闲端口，不产生冲突

### Requirement: 容器级 SSH 密码管理

SSH 密码 SHALL 在容器级别管理。创建容器时用户 MUST 设置该容器的 SSH 密码。用户可对单个容器重置 SSH 密码，重置 SHALL 即时生效。容器启动后受控端 SHALL 通过 `docker exec` 将密码注入容器。

#### Scenario: 创建时设置 SSH 密码
- **WHEN** 用户创建容器并在表单中设置 SSH 密码
- **THEN** 容器启动后受控端通过 `docker exec` 设置容器内 SSH 用户密码
- **AND** 确认 sshd 服务运行
- **AND** 密码与该容器绑定存储

#### Scenario: 重置容器 SSH 密码即时生效
- **WHEN** 用户对某个运行中容器重置 SSH 密码
- **THEN** 受控端通过 `docker exec` 立即更新该容器的 SSH 密码
- **AND** 新密码即时生效，用户可立即使用新密码 SSH 连接

### Requirement: 容器连接信息生成

容器创建成功后，系统 SHALL 向用户返回连接信息：SSH 连接信息（物理机 IP + 宿主 SSH 端口）与自定义应用连接信息（物理机 IP + 各应用宿主端口）。直连模式下使用物理机 IP。容器列表 SHALL 展示"IP地址"列（物理机 IP）。应用端口连接信息 SHALL 以表格形式展示，字段为"暴露端口"（宿主端口）与"容器内端口"。

#### Scenario: 获取直连连接信息
- **WHEN** 直连模式物理实例上的容器创建成功
- **THEN** 系统返回 SSH 连接信息 `物理机IP:宿主SSH端口` 与各应用端口连接信息
- **AND** 用户可在容器配置页面查看连接信息

#### Scenario: 容器列表展示 IP 与端口表
- **WHEN** 用户查看容器列表与连接信息
- **THEN** 容器列表展示"IP地址"列（物理机 IP）
- **AND** 连接信息中应用端口以表格展示，含"暴露端口"与"容器内端口"两列
### Requirement: 容器生命周期管理

用户 SHALL 能对自己拥有的容器执行启动、停止、重启、删除操作。容器删除时 SHALL 释放端口分配。存储池数据不随容器删除而删除。

#### Scenario: 停止与启动容器
- **WHEN** 用户停止一个运行中的容器
- **THEN** 受控端执行 `docker stop`，容器停止
- **AND** 用户可随后启动该容器

#### Scenario: 删除容器释放端口
- **WHEN** 用户删除一个容器
- **THEN** 受控端执行 `docker rm`，管理端释放该容器占用的宿主端口分配
- **AND** 容器关联的存储池数据保留不删除

### Requirement: 容器可见性 -- 仅数量

用户 SHALL 只能看到自己拥有的容器（及有权限访问的容器）。同物理机上其他用户的容器对当前用户不可见，但物理实例状态页 SHALL 展示聚合数量统计（「另有 N 用户 M 容器」）。导师可看到其课题组学生的容器。管理员可看到所有容器。

#### Scenario: 学生查看自己的容器
- **WHEN** 学生查看容器列表
- **THEN** 系统仅展示该学生创建的容器
- **AND** 不展示同机器上其他用户的容器

#### Scenario: 查看同机其他用户数量
- **WHEN** 用户查看物理实例状态
- **THEN** 系统展示该实例的聚合统计（当前用户数、容器数），如「另有 N 用户 M 容器」
- **AND** 不展示其他用户的具体容器详情

#### Scenario: 导师查看课题组学生容器
- **WHEN** 导师查看容器列表
- **THEN** 系统展示该导师课题组所有学生的容器


### Requirement: 容器状态实时更新

容器运行状态 SHALL 以受控端心跳回传为实时来源。管理端 SHALL 在心跳中根据受控端回传的容器状态更新容器状态，状态变更 SHALL 经既有 SSE 通道（container 事件）实时推送前端。除显式生命周期动作外，状态也反映受控端实际容器状态。

#### Scenario: 状态由心跳实时更新
- **WHEN** 心跳回传的某容器状态与管理端记录不一致
- **THEN** 管理端以心跳回传状态为准更新容器状态
- **AND** 经 SSE 推送状态变更至前端

#### Scenario: 生命周期动作后状态确认
- **WHEN** 用户对容器执行启停重启删
- **THEN** 动作下发受控端执行后，下次心跳回传确认该容器最新状态
- **AND** 前端状态实时更新
