## ADDED Requirements

### Requirement: 容器状态实时更新

容器运行状态 SHALL 以受控端心跳回传为实时来源。管理端 SHALL 在心跳中根据受控端回传的容器状态更新容器状态，状态变更 SHALL 经既有 SSE 通道（container 事件）实时推送前端。除显式生命周期动作外，状态也反映受控端实际容器状态。

#### Scenario: 状态由心跳实时更新
- **WHEN** 心跳回传的某容器状态与管理端记录不一致
- **THEN** 管理端以心跳回传状态为准更新容器状态
- **AND** 经 SSE 推送状态变更至前端

#### Scenario: 生命周期动作后状态确认
- **WHEN** 用户对容器执行启停重启删
- **THEN** 动作下发受控端执行后，下次心跳回传确认该容器最新状态
- **AND** 前端状态实时更新

## MODIFIED Requirements

### Requirement: 容器创建表单

用户 SHALL 通过表单创建容器。表单字段包含：选择镜像（仅限管理端已配置的镜像，下拉选择，不支持自由文本）、选择存储池（当前机器上用户拥有的或被共享授权的项目池，下拉展示各池状态）、资源限制（CPU、内存、SHM 为硬限制，GPU 显存为软限制）、声明容器内端口（SSH 22 + 自定义应用端口，所选镜像的应用端口自动预填，用户可增删）、设置容器 SSH 密码（必填）。资源限制字段 SHALL 默认填入当前用户可使用的最大值（取用户/课题组资源配额，无则取目标物理机总容量）并显示数值范围 [最小值, 最大值]。管理端根据表单生成 Docker 运行命令（MUST 包含 `--gpus all`、资源限制、端口映射），通过 WebSocket 下发给受控端执行。

#### Scenario: 学生创建容器
- **WHEN** 学生在分配到的物理实例上填写容器创建表单（含 SSH 密码）并提交
- **THEN** 管理端校验该学生有权使用该物理实例与所选存储池
- **AND** 管理端生成 Docker 运行命令（含 `--gpus all`、资源限制与端口映射）下发受控端
- **AND** 受控端调用 Docker API 创建并启动容器
- **AND** 容器启动后受控端注入 SSH 密码并回传端口映射结果
- **AND** 管理端向用户返回连接信息

#### Scenario: 资源限制默认值与范围
- **WHEN** 用户打开容器创建表单的资源限制字段
- **THEN** CPU/内存/GPU显存/SHM 默认填入当前用户可使用的最大值（用户/课题组配额，无则目标机总容量）
- **AND** 字段显示数值范围 [最小值, 最大值]
- **AND** 提交时后端校验限制不超过配额

#### Scenario: 镜像仅可选已配置镜像
- **WHEN** 用户在容器创建表单选择镜像
- **THEN** 下拉仅展示管理端已配置的镜像（自有/共享/公共库）
- **AND** 不允许自由文本输入镜像

#### Scenario: 容器内端口自动预填
- **WHEN** 用户选择某镜像
- **THEN** 该镜像的应用端口自动填入"容器内端口"
- **AND** 用户可增删端口，SSH 22 始终包含

#### Scenario: 无权使用该物理实例
- **WHEN** 用户尝试在未分配给自己的物理实例上创建容器
- **THEN** 系统拒绝并提示无权限

## MODIFIED Requirements

### Requirement: 容器连接信息生成

容器创建成功后，系统 SHALL 向用户返回连接信息：SSH 连接信息（物理机 IP + 宿主 SSH 端口）与自定义应用连接信息（物理机 IP + 各应用宿主端口）。直连模式下使用物理机 IP。容器列表 SHALL 展示"IP地址"列（物理机 IP）。应用端口连接信息 SHALL 以表格形式展示，字段为"暴露端口"（宿主端口）与"容器内端口"。

#### Scenario: 获取直连连接信息
- **WHEN** 直连模式物理实例上的容器创建成功
- **THEN** 系统返回 SSH 连接信息 `物理机IP:宿主SSH端口` 与各应用端口连接信息
- **AND** 用户可在容器配置页面查看连接信息

#### Scenario: 容器列表展示 IP 与端口表
- **WHEN** 用户查看容器列表与连接信息
- **THEN** 容器列表展示"IP地址"列（物理机 IP）
- **AND** 连接信息中应用端口以表格展示，含"暴露端口"与"容器内端口"两列
