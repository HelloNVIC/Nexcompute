## 一、立项（2026-07-21）

### [2] `/openspec-explore` + 完整产品愿景 —— 项目奠基提示词

> 项目名 Nexcompute（合算）
>
> Slogan 为"合众为一，算力无界" Unify Distributed GPU Power into One Seamless Platform
>
> 一套面向多台 Windows + GPU 主机的分布式容器算力管理平台
>
> 分为管理端和受控端，受控端有多个物理实例，管理端只有一个实例统一管理
>
> 主要功能为远程控制每一台主机的 Docker，向外分配资源
>
> （1）管理端
> 1、管理端也有前后端，后端使用 SpringBoot，前端使用 Vue 和 Ant Design，数据库使用 pg，消息队列使用 Redis，图表使用 ApexCharts
> 2、用户角色分为 管理员、学生、导师。
> 3、学生可用的功能模块有"物理实例状态"、"容器配置"、"镜像管理"、"存储池"、"特需工单提交"、"用户信息"、"课题组信息"
> 4、导师可用的功能模块包括学生可用的所有功能外还有"课题组信息"（有编辑按钮）、"学生资源分配"
> 5、管理员可用的功能模块包括"物理实例管理"、"镜像管理"、"存储池管理"、"用户与课题组管理"、"工单管理"、"用户权限矩阵配置"
>
> 物理实例的受控端通过向管理端定时心跳的模式保活，管理端可查看受控物理机的 CPU 占用、GPU 占用、CPU 温度、GPU 温度、各类配置信息、内存占用、进程等，可以控制受控物理机的重启、运行 Powershell 命令、息屏等操作。
>
> 存储池是指受控端在每台机器上建立的对应用户的文件夹，例如用户 A 在机器 01 上的存储池为 01-A。用户在某台所分配物理实例上创建容器时只能使用当前机器上面用户所属的存储池。存储池提供共享、迁移：共享是指用户可以将其存储池开放给其他用户访问，迁移是指用户可以将某台物理实例上属于自己的存储池移动到另一台物理实例上。
>
> 导师可访问和管理其课题组学生所拥有的所有资源，管理员可访问和管理所有用户的所有资源。
>
> （2）受控端
> 1、受控端使用 go 语言编写，可以编译为 exe 文件，有一个可视化窗口。
> 2、受控端可以检查当前 docker 环境（尤其是当前 docker 环境是否能够使用、远程访问），设置控制端 IP 地址、显示当前系统状态等
> 3、受控端可以防止当前系统进入睡眠、休眠状态。
> 4、受控端与管理端协商心跳保活机制，并能够执行管理端派发的命令，及时返回命令执行结果。
> 5、受控端的存储池根目录可以设置，设置后不可修改。
>
> 课题组信息由管理员和老师维护，老师在"学生资源分配"中可以创建学生注册链接，指定注册次数发给学生注册。
>
> 管理员可以设置一切用户。

*这一条直接定义了三端架构、角色模型、存储池语义与心跳协议，成为初版 17 份能力规格的源头。*

## 九、私有仓库镜像分发（2026-08-23 ~ 08-24，09-30 落地）

### [95] `/openspec-propose` + 分发模式重构提案 —— 项目最大架构变更

> 1、修改镜像的分发模式，改为上传至内网私有仓库 10.13.66.25:5000 中：
> 在前端，上传镜像时只需要询问用户原始镜像名、原始标签、应用端口、容器内挂载、使用说明，点击确定后新建记录。在操作中增加按钮"上传"，点击后显示命令，例如 原始镜像名 lab404-jupyter 原始标签 0.1，则
> docker tag lab404-jupyter:0.1 10.13.66.25:5000/lab404-jupyter:0.1
> docker push 10.13.66.25:5000/lab404-jupyter:0.1
